features

Everything the box needs, nothing it doesn't

AIBox is a small set of shell scripts.

$

One-command setup

A guided setup installs the guest, the SSH access, the services and the tunnel.

◳

A local web console

Services, updates, setup steps, snapshots and the VM lifecycle live in a browser tab.

⇄

One tunnel per service

Each service gets its own port forward and its own bind address.

◈

LAN exposure on demand

Expose a single service to the network, per service, without opening the whole VM.

◲

Snapshots

Create, revert and delete VM snapshots from the command line or from the console.

⌨

VS Code Remote-SSH

Open the shared folder in your own VS Code, with the path mapped for you.

↑

Updates you can see

Check the host and the VM for updates, then apply them one target at a time.

≡

Plain configuration

Every setting lives in one readable config file, and the console speaks English and French.

what it is

Three pieces, one workflow

AIBox is not a platform.

▤

The box

A KVM virtual machine on your own hardware.

◱

The console

A local web interface that shows what runs.

⇉

The tunnels

A user service forwarding one port per service over SSH.

how it works

Three commands and you are in

Clone the repository, run the setup, then pick how you want to work.

step 1
clone & setup 
git clone git@github.com:malko/aibox.git && cd aibox
./setup.sh

The setup walks through the VM, SSH, the services and the tunnel.

step 2
connect 
./aibox

One command opens an SSH session with every service forwarded.

step 3
web console 
./aibox web

The local console shows the services with a live availability dot.

network

One entry point, many services

commands

The CLI stays out of your way

A dozen commands cover the whole life of the box.

aibox startStart the VM and the tunnel
aibox statusState, service URLs, tunnel state
aibox webOpen the local web console
aibox exec <cmd>Run a command in the VM
aibox tunnel <cmd>Tunnel and LAN exposure
aibox vscode [dir]Open the VM in VS Code
aibox service-add <n> <p>Add a service
aibox service-listList the services
aibox snapshot <cmd>Create, list or delete snapshots
aibox update <target>Update a target
aibox check-updatesCheck for updates
aibox setup [step]Run the setup steps
aibox shutdownStop the tunnel and the VM
requirements

Almost nothing

A recent Linux host with KVM, and a guest image.

host

  • KVM/QEMU with libvirt
  • virsh and libvirt-client
  • BusyBox httpd for the web console
  • macOS is supported through Lima

guest

  • Ubuntu or Debian, with SSH access
  • 4 GB of RAM, 4 cores recommended
  • A dedicated user with sudo rights
  • The share is mounted with virtiofs

The questions people actually ask

Short answers, no marketing.

Does any of my data leave the machine?
No.
Do I need root on the host?
Only for a few setup steps.
How do I reach a service from another device?
Expose that service on the LAN.
Can I run my own services?
Yes.
How do I keep it up to date?
Check for updates, then apply them.
